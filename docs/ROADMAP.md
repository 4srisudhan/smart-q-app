# Smart Q: from prototype to real app

This prototype proves the idea. Below is a practical path to a product people can use every day.

## 1. Foundation (first)

- Move to React with Vite and TypeScript, one component per screen. Keep the current design, colors and copy.
- Make it a PWA: installable, works well on phones, and supports push notifications.
- Supabase for login, database and realtime. Never put the `service_role` key in the app. Use only the project URL and anon key.

## 2. Data model (Supabase / Postgres)

| Table | Key columns |
|---|---|
| profiles | id (auth user), role (customer or shopkeeper), name, contact, photo_url |
| shops | id, owner_id, name, type, lat, lng, code, avg_service_min, is_open |
| tickets | id, shop_id, customer_id, token_number, status (waiting, serving, done, left, skipped), joined_at, called_at, done_at |
| subscriptions | user_id, status, trial_ends_at, current_period_end |
| saved_shops | user_id, shop_id |

Rules (Row Level Security):
- A customer can read and change only their own profile, tickets, saved shops and subscription.
- A shopkeeper can read and manage tickets only for shops they own.
- Role is stored on the server and checked by policies, never trusted from the browser.
- Joining a queue and calling the next token are database functions, so token numbers are issued atomically and two people never get the same number.

## 3. Real features to build next

- Realtime queue: shop and customer screens subscribe to ticket changes, so Call Next updates every phone.
- Payments: Razorpay subscriptions with UPI. Verify the webhook signature on the server and store only the plan status. The 3 day trial lives in the database, not the browser.
- Maps: Leaflet with OpenStreetMap tiles, or Mapbox, plus a routing service for real road distance.
- Push notifications for "turn is near", then SMS or WhatsApp later.
- Printable QR poster for each shop (the QR files in `assets/qr` are a start). Make the QR a link such as `https://yourdomain/join/<shop-code>` so any phone camera works.

## 4. Ideas that make it better

1. Learn the real average service time from served tickets (a moving average), instead of relying on a number the shop types in.
2. No-show handling: a short grace timer after a token is called, then skip to the next person.
3. "I am here" check-in or a distance limit, so people cannot join a queue from far away and never arrive.
4. Peak hour insights for shops: busiest times, average wait, tickets served per day.
5. Multi-counter queues and appointments for clinics and offices.
6. Accessibility: larger text option, screen reader labels, and voice announcements of the called token.
7. Tamil and Hindi language support.

## 5. Before public launch

- Custom domain, favicon, and no "made with" badge.
- Privacy Policy and Terms reviewed by a lawyer (the text in `js/app.js` is a template).
- Follow the DPDP Act 2023: clear consent, a way to delete data, and a named contact.
- Replace the sample name "Alex Rivera" and any demo data.
- Replace the current logo with a designer-made vector logo, and run a trademark search. A logo generated by an AI tool is hard to protect and may resemble an existing mark.
- Test on real Android and iPhone devices, including camera scanning and location.
